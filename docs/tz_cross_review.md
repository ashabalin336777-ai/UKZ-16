# Кросс-ревью Phase 1 и ТЗ УКЗ-16 v1.0

Дата сверки: 13 октября 2026.  
Объект: код `research-v0.1` (коммит `f6b6948`).  
Эталон: ТЗ «Нейро-сотрудник клинической валидации HEALTH_ID», версия 1.0 от 16 августа 2026.

## Вердикт

Phase 1 — исследовательский каркас, а не приёмка по полному ТЗ. Назначение, запрет диагноза, запрет предсказания ИМТ, отказ считать hMental без психометрии, персональный коридор без текущей точки и persistence по уникальным датам совпадают с ТЗ.

Главный конфликт: итоговый HEALTH_ID при неполных компонентах **перенормирует** оставшиеся веса. План Phase 1 (1C+2B) это разрешил (`allow_weighted_partial`). §4, §7 и §12 ТЗ это запрещают и требуют `health_id.value = null`.

## Конфликты с ТЗ

1. **Перенормировка весов.** `_aggregate` в `src/ukz16/engine/calculator.py` делит сумму на вес доступных компонент. При одном hBody (вес 0.60) выдаётся числовой индекс.
2. **Укороченный proxy под именем hBody.** Без роста и веса hBody всё равно получает число и входит в индекс. ТЗ §8 требует отдельное имя, формулу, нормы и карточку для укороченного показателя. Полный АП Баевского в коде не считается — это правильно, но отдельного результата `not_calculable: missing_height_weight` для ИМТ и АП нет (A16-02).
3. **Словарь статусов компонента.** ТЗ §12: `measured | derived | experimental | missing`. Код: `ok | partial | not_calculable | blocked`.

## Что совпадает

- Research use only и `diagnosis_claim = false`.
- hMental не считается без `psychometrics.validated`.
- Посещаемость не подменяет мотивацию / hSocial.
- ИМТ не предсказывается по косвенным данным.
- Коридор исключает текущую дату; persistence — по уникальным датам.
- Жёсткий отказ при отсутствии согласия, неизвестной единице и чужом протоколе.
- Review pending / confirmed / rejected не стирает результат; audit пишется.
- Drift не обновляет модель (`auto_update = false`).
- Экспорт работодателю закрыт ответом 403 (это не разделение контуров).

## Частично

- F16-01: нет качества сигнала, флагов артефактов и справочника единиц.
- F16-05: нет альтернативного объяснения и следующего шага.
- Неопределённость — дополнение полноты, не интервал.
- API короче §14: нет `/validation/metrics`, trajectory без диапазона дат, model card без версии в пути.
- R0 и R1 — черновики и pytest, без подписей и без отчёта «100% критических тестов».
- A16-тесты в репозитории не равны чеклисту A16-01…A16-12 один к одному.
- Leakage и group holdout — функции для тестов, не пайплайн обучения.

## Осознанно вне Phase 1

SVS, HRV, rPPG, 12 систем, боевая ЕЦОЗ, MFA, TLS/mTLS, шифрование, backup, схемы raw/normalized/research/audit, idempotency_key, R2–R4 на клинических данных, p95 и 99.5%.

## Что закрыто в research-v0.2

1. Перенормировка отключена. Нет всех трёх компонент — `health_id.value = null`.
2. `bmi` и `ap_baevsky` — отдельные результаты. Без роста/веса статус `missing`, причина `missing_height_weight`. В индекс не входят.
3. Статусы компонента: `measured | derived | experimental | missing`.

Дальше по ТЗ остаются подписи R0/SAP, протокол A16-01…A16-12 и этапы вне Phase 1.
