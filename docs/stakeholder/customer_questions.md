# Вопросы заказчику — УКЗ-16 / HEALTH_ID

Цель: снять блокеры перед клинической валидацией (R2–R4) и production-контуром.  
Ответы можно кратко (пункт + комментарий / ссылка на документ).

---

## 1. Назначение и границы продукта

1. Подтверждаете ли формулировку **research use only** до завершения R2–R4?  
2. Кто юридически владелец результата (индекс, модель, отчёты): заказчик / подрядчик / совместное?  
3. Нужен ли отдельный контур «агрегаты для работодателя» (без индивидуальных HEALTH_ID)? Если да — какие метрики допустимы?  
4. Есть ли запреты регулятора (152-ФЗ, отраслевые приказы) сверх уже заложенных в ТЗ?

## 2. Данные и когорта

5. Какой источник данных для **R2** (название БД/выгрузки, период, N субъектов, N визитов)?  
6. Когда ожидается доступ к данным и в каком формате (API ЕЦОЗ, JSON/CSV, FHIR, иное)?  
7. Есть ли уже **informed consent / research consent** на вторичное использование?  
8. Нужна ли псевдонимизация на стороне заказчика до передачи подрядчику?  
9. Какие сайты/площадки планируются для **R3** (внешняя транспортабельность)?  
10. Есть ли golden-набор с разметкой врача для калибровки порогов?

## 3. Интеграция ЕЦОЗ / МИС

11. Endpoint и контур (тест / stage / prod) для чтения encounter ПрМО?  
12. Финальный список полей и единиц измерения (рост, вес, АД, пульс, психометрика, social)?  
13. Как передаётся флаг «клинически подтверждённое хроническое» из EMR?  
14. Требования к idempotency и повторной доставке событий со стороны МИС?  
15. Кто выдаёт и ротирует токены доступа к ЕЦОЗ?

## 4. Клиническая валидация и люди

16. Сколько медицинских работников участвует в **R4** (review) и на каких площадках?  
17. Какой целевой горизонт: только сигнал врачу или также процесс допуска (мы закладываем **запрет** допуска из модуля)?  
18. Кто подписывает протоколы R0/SAP и акт аналитической приёмки A16?  
19. Нужна ли интеграция с ЭП / 63-ФЗ на clinical review в первой промышленной волне?

## 5. Модель и экспериментальные сигналы

20. Утверждаете ли текущие веса 0.60 / 0.25 / 0.15 как исходные для R2 или есть альтернатива?  
21. HRV / rPPG / voice (SVS): остаются **experimental** или есть план отдельного протокола валидации?  
22. Какие устройства и версии протоколов ПрМО обязательны на площадках?

## 6. Безопасность и эксплуатация

23. Целевой IdP: Keycloak заказчика или иной OIDC? Требуется ли MFA для всех ролей?  
24. Кто хостит: контур заказчика / подрядчика / гибрид?  
25. Требования к TLS/mTLS, шифрованию дисков, сроку хранения, backup RPO/RTO?  
26. Нужен ли Vault (или аналог) в контуре заказчика для секретов и pepper псевдонимизации?  
27. Политика логирования: допустимы ли технические метрики без PHI в внешней системе (OTEL)?

## 7. Приёмка и сроки

28. Критерии «готово к пилоту» vs «готово к промышленной эксплуатации» с вашей стороны?  
29. Желаемые даты: доступ к данным → старт R2 → R3 → R4 → решение go/no-go?  
30. Единая точка контакта со стороны заказчика (данные / клиника / ИБ / интеграция)?
